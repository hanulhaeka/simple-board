# 세션 기반 인증 및 인가 직접 구현

# 1. 개요

Spring Security를 활용하여 인증(Authentication)과 인가(Authorization) 기능을 구현하기에 앞서,

인증과 인가의 동작 과정과 구조를 이해하기 위해 해당 기능을 직접 구현하였다.

이를 위해 raw-auth 브랜치를 생성하여 세션 기반의 인증 처리와 권한 기반 접근 제어 기능을 구현하였다.

# 2. 인증

## 로그인 처리 과정

1. 클라이언트 로그인 페이지 요청 및 로그인 페이지 반환
2. 클라이언트가 아이디와 비밀번호를 서버로 전송
3. 컨트롤러에서 요청 데이터를 검증한 후 로그인 DTO를 서비스 계층으로 전달
4. 서비스 계층에서 전달 받은 아이디를 기반으로 리포지토리에서 사용자 엔티티를 조회
5. 조회된 사용자 엔티티의 존재 여부와 비밀번호 일치 여부 검증
6. 검증 결과를 Optional<User> 형태로 컨트롤러에 반환
7. 반환된 Optional 객체가 비어 있을 경우 BindingResult에 오류를 추가하고 로그인 페이지를 다시 반환
8. 사용자 정보가 존재할 경우 HttpSession에 SessionUser 객체를 저장하여 로그인 상태를 유지
9. 로그인 성공 후 home URL로 리다이렉트

## 세션 처리

- 인터셉터(Interceptor)를 통해 HTTP 요청에서 HttpSession에 SessionUser 객체가 존재하는지 확인
- SessionUser 객체가 존재하면 요청을 정상적으로 진행하고, 존재하지 않으면 현재 요청 URL을 리다이렉트 주소로 쿼리 파라미터에 포함하여 로그인 페이지를 리다이렉트
- 해당 인터셉터를 스프링 인터셉터 체인에 등록하고, 로그인이 필요한 URL 패턴에 대해 인터셉터가 동작하도록 설정

## 로그아웃

- 로그아웃 요청이 발생하면 ‘HttpSession’의 ‘invalidate()’ 메서드를 호출하여 세션 정보를 삭제하고, 이후 홈 URL로 리다이렉트

# 3. 인가

## 개요

- 비로그인 사용자는 게시글 읽기, 로그인, 회원가입만 가능
- 로그인 사용자는 게시글 작성이 가능
- 로그인 사용자 중 일반 유저는 본인이 작성한 게시글만 수정 및 삭제 가능
- 로그인 사용자 중 관리자는 모든 글 수정 및 삭제 가능

## 비로그인

- 로그인 체크 인터셉터를 스프링 인터셉터 체인에 등록
- 게시글 조회, 로그인, 회원 가입 관련 URL은 인터셉터의 제외 경로로 설정
- 따라서 비로그인 사용자는 게시글 조회, 로그인, 회원 가입 기능만 사용

## 로그인

- 비로그인 사용자에게 허용된 URL을 제외한 모든 요청에 대해 로그인 체크 인터셉터가 동작하도록 설정
- 게시글 작성, 수정, 삭제 요청은 세션 정보를 기반으로 로그인 여부를 확인

### 일반 유저

- 일반 사용자가 특정 게시글을 조회할 때, 요청한 게시글 엔티티의 작성자 ID와 세션에 저장된 사용자 ID가 일치하는 경우에만 수정 및 삭제 버튼이 포함된 뷰를 반환
- 일반 사용자의 게시글 수정 또는 삭제 요청이 들어오면, 게시글 엔티티의 작성자 ID와 세션의 사용자 ID가 일치하는 경우에만 수정 또는 삭제를 수행
- 작성자 본인 여부 검증은 서비스 계층에서 수행

### 관리자

- 게시글 조회 시 세션에 저장된 권한이 관리자이면, 모든 게시글에 대해 수정 및 삭제 버튼이 포함된 뷰를 반환
- 게시글 수정 또는 삭제 요청 시 세션에 저장된 권한이 관리자이면 수정 또는 삭제를 수행
- 컨트롤러 계층은 세션 정보를 확인한 뒤 이를 서비스 계층에 전달하고, 실제 권한 검증 및 처리 여부 판단은 서비스 계층에서 수행
